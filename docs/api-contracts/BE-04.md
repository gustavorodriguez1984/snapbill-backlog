## POST `/api/v1/inventory/periods/fiscal-close`

**Auth:** JWT con rol `TenantAdmin` y claim `tenant_id`.

**Body**

```json
{
  "fiscalYearId": "uuid"
}
```

`fiscalYearId` = año fiscal **que se cierra** (ej. 2026).

### Response 200

```json
{
  "closedFiscalYearId": "uuid",
  "year": 2026,
  "incomingFiscalYearId": "uuid",
  "incomingYear": 2027,
  "isClosed": true,
  "productsOpened": 42,
  "closedAt": "2026-12-31T23:59:59Z"
}
```

- `productsOpened`: filas creadas en `ProductFiscalOpenings` para el **año entrante** (2027).
- Origen: snapshot de diciembre (`ProductMonthlyHistories` del mes 12).

### Errores

| HTTP | errorCode | Cuándo |
|------|-----------|--------|
| 400 | `FiscalYearClose.OpenPeriodsRemaining` | algún mes del año sigue abierto (detalle lista meses) |
| 404 | `FiscalYearClose.NotFound` | `fiscalYearId` inexistente en el tenant |
| 409 | `FiscalYearClose.AlreadyClosed` | el año ya fue cerrado |
| 409 | `FiscalYearClose.NextFiscalYearNotFound` | no existe el año entrante (precargar vía BE-01 / job 15-dic) |
| 409 | `FiscalYearClose.ConcurrencyConflict` | conflicto `RowVersion` en cierre simultáneo |
| 403 | — | sin rol TenantAdmin |

### Efecto en transacciones (BE-02)

Tras el cierre, `FiscalYear.IsClosed = true` y `IDocumentPeriodGuard` rechaza operaciones en ese año con **400** `FiscalYearClosed` (además de meses cerrados).

---

## Prerrequisitos

1. Los **12** `TenantPeriod` del año tienen `isClosed = true` (BE-03).
2. Existe el `FiscalYear` del **año siguiente** para el tenant (BE-01).

---

## Verificación manual

1. Cerrar los 12 meses de 2026.
2. Confirmar año 2027 precargado.
3. `POST .../fiscal-close` `{ "fiscalYearId": "<2026>" }` → 200.
4. SSMS: `FiscalYears.IsClosed = 1` (2026), filas en `ProductFiscalOpenings` con `FiscalYearId` de 2027.
5. Repetir → 409 `FiscalYearClose.AlreadyClosed`.
